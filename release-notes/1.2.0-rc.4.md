## reflex v1.2.0-rc.4

A real backup for commissioning values, and an in-app update that recovers
from its own failures. Firmware and UI must be updated together. Also
included, **experimental and off by default:** compensation for the
servo-drive latency that makes the carriage coast past an electronic stop,
tested only on the development lathe.

### ⚠ Upgrade notes
- **Firmware and UI move together** (register protocol 11). The in-app update
  does both. If the two disagree, Sync Enable refuses to turn the feed on
  rather than run a mismatched pair.
- **Stop coast correction is experimental.** It ships OFF. It has only been
  calibrated and tested on one machine (the development lathe), and there is
  no calibration wizard yet. On any other lathe, leave it off, or turn it on
  only knowing the correction may be the wrong size for your machine.

### Backup and restore
- **Setup → Backup** collects everything in one screen: export to and import
  from a USB stick, and optional sync to a private GitHub gist (off by
  default; sign in by device code, with a QR code so you don't have to type
  the URL).
- Commissioning values (backlash, scale ratios, axis setup and the rest) are
  now recorded on the card every time they change, so a changed value leaves
  a history instead of silently overwriting the old one.
- Every backup is stamped with the firmware revision it came from.
- The last two settings stored in `ui/config.ini` (use case, current mode)
  move to the config directory with everything else. This migrates
  automatically, once.

### Safer in-app updates
- Firmware transfer resumes after a dropped serial link instead of failing,
  and a failed update never leaves the controller waiting in its bootloader.
- If the UI half of an update fails after the firmware was flashed, both
  halves are put back as they were.
- The update checks that it can write the UI's Python environment before
  flashing anything, not after.

### Stop coast correction (experimental, opt-in)
**Why it exists:** the servo drive has latency. When the firmware stops
issuing steps at the stop position, the drive keeps moving for a short time
before it actually halts, so the carriage coasts past the shoulder. The
faster the feed, the further it coasts. That is a hardware limitation. The
firmware stops on time; this feature works around the drive.

**What it does:** the UI predicts the coast from the live Z rate and asks the
firmware to stop early by that amount, plus a margin. The stop target itself
is never changed.
- Development lathe, real cuts to a shoulder at .020 and .040 in/rev and a
  fine feed: 9 of 9 stops landed 1–4 counts (5–20 µm) short, none past. In an
  air test with the correction off, every stop ran 7 counts (35 µm) past.
- Turn it on in the ELS settings (gear on the ADV bar) → Advanced →
  **Stop coast correction**. The margin is **Coast margin (Z counts)**,
  default 1.
- Calibrated up to about 40 in/min of Z feed. Above that it holds its largest
  value and says so on screen.

### Fixes
- Dark mode: most values on Setup → System were invisible.
- The UI no longer fails to start when the OS refuses a wifi change.
- Flight recorder: a negative distance-to-go was recorded as ~4.29 billion.

### Verified
Bench-tested on the development lathe 2026-09-19: an air go/no-go, then real
shoulder cuts. The update recovery paths are tested against injected
link failures. CI green on the promoted commit.
